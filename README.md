# CCI Country Audit

Приложение для аудита стран на основе карты экспансии Coral Club (Country Expansion Map v3, инструмент Кристиана).

## Как это работает

1. Руководитель дивизиона входит по личному паролю.
2. Вписывает название страны: если она уже есть в его списке, она открывается, иначе создаётся новая.
3. Переключателем выбирает текущую стадию страны (1–6).
4. Все стадии до текущей включительно проходит по чек-листу: по каждой строке отмечает «Есть» или «Нет». Для «Нет» оставляет пояснение (что мешает, план, срок).
5. Раздел «Пробелы» собирает все «Нет» с пояснениями. Любую страну можно выгрузить в CSV.
6. Администратор в админ-панели заводит руководителей и выдаёт им пароли. Там же он видит сводку по всем странам и открывает любой аудит только для чтения.

Каждое изменение сохраняется в Supabase сразу. Данные каждого руководителя изолированы: он видит и меняет только свои страны, поэтому записи разных людей не пересекаются.

## Устройство

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка и стили (светлая тема) |
| `app.js` | Логика: вход, выбор страны, стадии, чек-листы, сохранение, админка |
| `data.js` | Тексты этапов из исходного инструмента (RU/EN), без изменений |
| `config.js` | URL проекта Supabase и публичный ключ |
| `supabase/schema.sql` | Таблицы и функции базы |

### База (Supabase)

- `ca_users`: руководители, пароль хранится как bcrypt-хеш.
- `ca_sessions`: сессии входа, действуют 30 дней.
- `ca_audits`: страна руководителя и её текущая стадия.
- `ca_items`: ответы по строкам чек-листа: стадия, раздел, текст пункта, `yes`/`no`, комментарий.

Сайт не обращается к таблицам напрямую. RLS включён без политик, весь доступ идёт через функции `ca_*`, и каждая из них проверяет токен сессии и владельца записи.

### Установка базы

1. `supabase/schema.sql` создаёт таблицы и все функции (в проекте уже применён, кроме пяти функций из следующего шага).
2. `supabase/finish.sql` создаёт пять функций с удалением строк: вход, сохранение строки, удаление страны, заведение и удаление руководителя. Supabase → SQL Editor → вставить файл → Run.

### Первый администратор

Администратор уже создан. Если понадобится ещё один без админ-панели, выполните в SQL Editor:

```sql
insert into public.ca_users(label, pass_hash, is_admin)
values ('Ваше имя', extensions.crypt('ВАШ_ПАРОЛЬ', extensions.gen_salt('bf', 10)), true);
```

Остальных руководителей администратор заводит в админ-панели.

## Публикация

Сайт статический, его публикует GitHub Pages из ветки `main`, корневая папка. Сборка не нужна.
